# AGENTS.md

Personal portfolio site for Johannes Fischer. Static React SPA deployed to GitHub Pages.

## Tech Stack

- **Vite+** — unified toolchain (`vp`): Vite/Rolldown build, Oxlint, Oxfmt, Vitest, package management
- **React 19** — functional components, hooks
- **TypeScript** — strict mode, ES2023 target
- **Panda CSS** — atomic CSS-in-JS, design tokens, CVA variants
- **Lucide React** — icons
- **Motion** — animations
- **Storybook** — component development and documentation (`@storybook/react-vite`)
- **Chromatic** — visual regression testing and Storybook publishing
- **Vitest** + **@testing-library/react** — unit/hook tests, `jsdom` environment

Vite is installed as the Vite+ core (`vite: npm:@voidzero-dev/vite-plus-core`), pinned via `overrides`. Oxlint replaces ESLint and Oxfmt replaces Prettier — there is no `eslint.config.js` and no `.prettierrc.json`.

## Commands

```bash
vp install         # install dependencies (run after pulling)
vp dev             # dev server with HMR
vp build           # production build → dist/
vp preview         # preview production build
vp check           # format + lint + type check
vp lint            # Oxlint (config in vite.config.ts → lint)
vp fmt .           # Oxfmt (config in vite.config.ts → fmt)
vp test            # Vitest (watch locally, single run when CI is set)
vp run storybook   # Storybook dev server (http://localhost:6006)
vp run chromatic   # publish Storybook to Chromatic (requires .env)
vp run prepare     # regenerate Panda CSS types
vp config          # install the Vite+ git hook dispatcher (.vite-hooks/_)
vp staged          # run staged-file checks (config in vite.config.ts → staged)
```

`vp <name>` is a built-in command; `vp run <name>` runs a `package.json` script or a `vite.config.ts` task. The `dev`, `build`, `preview`, `test` and `format` scripts in `package.json` only delegate to the matching `vp` command, so call `vp` directly. `npm run <script>` still works for the Storybook, Chromatic and Panda scripts.

Run `vp check && vp test` before committing.

A Vite+ `pre-commit` hook (`.vite-hooks/pre-commit` → `vp staged`) runs `vp lint --fix` and `vp fmt` on staged `*.{ts,tsx}`, and `vp fmt` on staged `*.{css,json,md}`. The checks are configured in `vite.config.ts` → `staged`. `vp config` installs the hook dispatcher under `.vite-hooks/_` (gitignored, regenerated); `vp hooks status` shows whether hooks are active.

Chromatic requires a `.env` file with `CHROMATIC_PROJECT_TOKEN=<token>`. The `.env` is gitignored.

## Project Structure

```
.storybook/        # Storybook config (main.ts, preview.tsx, modes.ts)
index.html         # main entry
kicks/index.html   # "kicks" entry
mujin/index.html   # "mujin" entry
src/
├── components/    # reusable UI (Button, Carousel, Header, Footer, …) + *.stories.tsx
├── hooks/         # shared hooks (useEscapeKey, useFocusFirst, useLockBodyScroll) + *.test.ts
├── sections/      # page sections (Hero, Skills, Testimonials, Career)
├── styles/        # CVA variant definitions (button.ts)
├── kicks/         # "kicks" page components/sections
├── mujin/         # "mujin" page components/sections
├── App.tsx        # root, theme provider
├── ThemeContext.tsx
├── usePreferredColorScheme.ts
├── const.ts       # URLs and constants
```

Three HTML entries are declared in `vite.config.ts` → `build.rollupOptions.input`; React and React DOM are split into a `vendor` chunk via `manualChunks`.

## Code Conventions

### Components

- Files: PascalCase (`Button.tsx`, `HeadingGroup.tsx`)
- Hooks/utils: camelCase (`usePreferredColorScheme.ts`)
- Constants: UPPER_SNAKE_CASE (`COLOR_SCHEMES`, `URLS`)
- Use `React.FunctionComponent<Props>` type for components
- Default exports for components

### Styling

All styling via Panda CSS — no traditional CSS files.

```typescript
import { css } from "../../styled-system/css";
import { grid } from "../../styled-system/patterns";

<div className={css({ bg: "primary", color: "neutral", p: 4 })} />
```

Responsive values use arrays: `{ p: [2, 4, 6] }` = mobile / tablet / desktop.

Button variants defined with `cva()` in `src/styles/button.ts`. Compose via `buttonStyles({ variant, size, disabled })`.

### Theme

Dark/light theme via `ThemeContext`. System preference detected by `usePreferredColorScheme` using `useSyncExternalStore`. Applied as `data-color-mode` attribute on root div.

### Data

No external API calls. Content is hardcoded in section components. Shared URLs/constants live in `src/const.ts`.

## Storybook & Chromatic

### Story conventions

- Stories co-located with components: `src/components/ComponentName.stories.tsx`
- CSF3 format — `Meta` and `StoryObj` imported from `@storybook/react-vite`

### Decorators & global config

All stories are automatically wrapped (via `.storybook/preview.tsx`) in:

1. `withThemeByDataAttribute` — sets `data-color-mode` attribute to match the selected theme
2. A `ThemeContext` decorator — provides theme value and a padded `bg`/`color` container

`tags: ["autodocs"]` is set globally — every story gets an auto-generated docs page.

### Chromatic modes

Light and dark snapshots are captured for every story globally. No per-story config needed unless overriding. Modes are defined in `.storybook/modes.ts` and applied in `preview.tsx`:

```ts
parameters: {
  chromatic: {
    modes: {
      dark: allModes["dark"],
      light: allModes["light"],
    },
  },
},
```

## Testing

- **Vitest** via `vp test` — `vitest.config.ts` sets `environment: "jsdom"`, no global setup file
- `clearMocks: false` is set for Vitest v4 compatibility (mock call history is preserved); remove once no test relies on calls from setup or earlier tests
- **@testing-library/react** — `renderHook`/`act` for hooks, no components tested yet
- Test files co-located with the source: `src/hooks/useFocusFirst.ts` → `src/hooks/useFocusFirst.test.ts`
- `vp test` watches locally and switches to a single run when `CI` is set (GitHub Actions sets this automatically)
- CI: `.github/workflows/ci.yml` runs lint + test on every PR and on pushes to non-`main` branches

## TypeScript

Strict mode enabled. Key flags: `noUnusedLocals`, `noUnusedParameters`, `noUncheckedSideEffectImports`. Target ES2023 with bundler module resolution.

Type checking runs through Oxlint: `lint.options.typeAware` and `typeCheck` are enabled, so `vp lint` and `vp check` report type errors.

## Linting & Formatting

Both are configured in `vite.config.ts`, not in separate config files.

- `lint` — Oxlint. Plugins `oxc`, `typescript`, `unicorn`, plus the JS plugins `vite-plus/oxlint-plugin`, `eslint-plugin-perfectionist` and `eslint-plugin-storybook`. The `correctness` category is `warn`; `dist` is ignored. Overrides cover `**/*.{ts,tsx}` (core, TypeScript, React and perfectionist rules), story files, and `.storybook/main.*`.
- `eslint-plugin-perfectionist` — imports, object properties, JSX props and more sorted natural/ascending.
- `fmt` — Oxfmt: double quotes, semicolons, 2-space indent, `printWidth: 80`, trailing commas everywhere, `sortPackageJson: false`.
- `vite-plus/prefer-vite-plus-imports` is an error — import from `vite-plus`, not `vite`.

## Panda CSS Notes

Config in `panda.config.mjs`. After modifying the config, run `vp run prepare` to regenerate `styled-system/`. Never manually edit files in `styled-system/`.

Design tokens: semantic color tokens for light/dark, typography tokens (Inter for body, Space Grotesk for headings), custom `scrollable` pattern.

## Deployment

Push to `main` → GitHub Actions builds and deploys to GitHub Pages automatically.

Workflow (`deploy.yml`): `npm ci` → `npm run build` (→ `vp build`) → build Storybook docs → upload `dist/` → deploy to Pages. Linting and tests are not gated here — they run in `ci.yml` instead.

# Using Vite+, the Unified Toolchain for the Web

This project is using Vite+, a unified toolchain built on top of Vite, Rolldown, Vitest, tsdown, Oxlint, Oxfmt, and Vite Task. Vite+ wraps runtime management, package management, and frontend tooling in a single global CLI called `vp`. Vite+ is distinct from Vite, and it invokes Vite through `vp dev` and `vp build`. Run `vp help` to print a list of commands and `vp <command> --help` for information about a specific command.

Docs are local at `node_modules/vite-plus/docs` or online at https://viteplus.dev/guide/.

## Built-in Commands vs Scripts

`vp <name>` runs a built-in command. `vp run <name>` runs a `package.json` script or a `vite.config.ts` task. Scripts cannot overwrite built-ins, so `vp dev` and `vp run dev` may do different things. Check `package.json` and `vite.config.ts` first, and run `vp run <name>` when the project defines a script or task with that name.

## Tool Versions

Run `vp toolchain` to show versions and relationships in the active Vite+
release. Add a tool name to select part of the graph. For example, run
`vp toolchain vite`. Use `--global` to ignore the local `vite-plus` package. Use
`vp why <package>` to show the package-manager dependency graph.

## Review Checklist

- [ ] Run `vp install` after pulling remote changes and before getting started.
- [ ] Run `vp check` and `vp test` to format, lint, type check and test changes.
- [ ] Check if there are `vite.config.ts` tasks or `package.json` scripts necessary for validation, run via `vp run <script>`.
- [ ] If setup, runtime, or package-manager behavior looks wrong, run `vp env doctor` and include its output when asking for help.
